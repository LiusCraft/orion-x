# Agent 记忆能力调研（orion-x）

## 背景与目标
本项目需要支持三种记忆模式：
- **无记忆**：不保存历史，不注入上下文。
- **临时记忆（Session）**：仅当前会话内可回忆，进程/会话结束即失效。
- **长期记忆（Long-term）**：持久化存储，跨会话可检索。

目标是在现有语音对话架构中，以较低改造成本实现记忆能力，并提供清晰的可落地实现路径。

---

## 常见记忆方式对比

### 1. 会话缓冲（Conversation Buffer）
**方式**：保留最近 N 轮对话，直接拼接注入 LLM。

**优点**：
- 实现简单
- 响应一致性高

**缺点**：
- Token 快速膨胀
- 过多历史会降低模型质量

**适用**：短会话、实时语音交互。

---

### 2. 摘要记忆（Summary Memory）
**方式**：定期对历史对话总结，保留摘要 + 最近 N 轮。

**优点**：
- 记忆容量高
- Token 成本稳定

**缺点**：
- 摘要依赖 LLM，可能丢失细节
- 实现复杂度中等

**适用**：需要跨多轮保持上下文但成本敏感的场景。

---

### 3. 结构化事实记忆（Fact Memory）
**方式**：提取用户偏好、事实（如“用户住在上海”），结构化存储。

**优点**：
- 精确可控
- 更适合个性化体验

**缺点**：
- 需要抽取器（规则或 LLM）
- 需要管理隐私、时效

**适用**：个性化推荐、长期陪伴型助手。

---

### 4. 向量记忆（Vector Memory / RAG）
**方式**：将对话与事实向量化，使用向量库检索。

**优点**：
- 语义检索能力强
- 可扩展至知识库

**缺点**：
- 引入向量库依赖
- 需要 embedding 与索引维护

**适用**：复杂知识检索、跨领域记忆。

---

## 关键权衡
| 维度 | 缓冲 | 摘要 | 结构化 | 向量 |
|---|---|---|---|---|
| 延迟 | 低 | 中 | 中 | 高 |
| Token 成本 | 高 | 低 | 低 | 中 |
| 实现复杂度 | 低 | 中 | 中 | 高 |
| 可维护性 | 中 | 中 | 中 | 低 |
| 隐私风险 | 中 | 中 | 高 | 高 |

---

## 推荐落地方案
**阶段 1（当前）**：
- Session Buffer + Summary（可选）
- SQLite + FTS 做长期记忆检索

**阶段 2（后续）**：
- 加入向量索引（Qdrant/PGVector）
- 混合检索：FTS + 向量

---

## 结论
基于当前 orion-x 架构与依赖约束，**优先采用 Session Buffer + SQLite FTS 的组合**，既保证低成本快速落地，又可平滑升级到向量记忆方案。
